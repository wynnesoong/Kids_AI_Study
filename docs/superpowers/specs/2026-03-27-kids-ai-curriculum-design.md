# Kids AI Study — 兒童 AI 教學課程設計規格

## 概覽

| 項目 | 內容 |
|------|------|
| **對象** | 10 歲 & 12 歲，有 Scratch 程式設計基礎 |
| **總時長** | 約 5 小時（260 分鐘課程 + 40 分鐘彈性/休息） |
| **安排方式** | 彈性模組化，隨時可停下次接續（模組 1-2 可獨立；模組 3-5 有漸進依賴） |
| **最低方案需求** | Claude Pro 帳號（需要 Projects、Cowork、Dispatch 功能） |
| **休息建議** | 每個模組之間休息 10 分鐘，或每 40-50 分鐘休息一次 |
| **核心目標** | 啟發興趣為主，讓孩子覺得好玩、產生持續學習的動力 |
| **設備** | 每人一台電腦，各自獨立操作 |
| **成品** | GitHub 上的小專案 + 學習筆記 |

## 設計原則

1. **不幼稚** — 用對等的語氣教學，不用卡通化比喻，尊重他們的理解力
2. **每個模組都有「學」和「玩」** — 理論輕量有趣，實作佔大比例
3. **漸進式設計** — 模組 1-2 可獨立上課；模組 3-5 建立在前面的基礎上，建議按順序進行
4. **Prompt 工程貫穿全程** — 不獨立成模組，融入每個環節自然學會
5. **實作步驟要詳細** — 像操作手冊，步驟清楚但解釋有深度，讓孩子和家長都能看懂又不會太淺

## 模組 1：AI 大發現（40 分鐘）

**目標**：建立對 AI 的正確認知，體驗 AI 的真正實力

### 學（15 分鐘）

#### 1.1 AI 的本質
- AI 是一種「從大量資料中找出規律」的程式
- 用 Scratch 類比建立橋樑：Scratch 是你寫條件判斷讓角色動，AI 是電腦自己從幾十億筆文字中「學會」語言規則
- 重點區分：傳統程式 = 人寫規則；AI = 從資料學規則

#### 1.2 大語言模型怎麼運作
- **Token** — AI 不是一個字一個字讀，它把文字切成一個個小碎片（Token），中文大約一個字是一個 Token
- **預測下一個字** — LLM 的核心能力就是根據前面的文字，預測下一個最可能出現的字。像在玩超級進階版的「文字接龍」
- **幻覺（Hallucination）** — 因為它是「預測」不是「查資料」，所以有時候會非常自信地說出完全錯誤的東西。這不是 bug，是這個技術的本質特性

#### 1.3 AI 的能力邊界
- **能做**：寫程式、翻譯、分析資料、創作文章、辨識圖片、整理筆記
- **不能做**：真正理解意義、擁有情感、保證 100% 正確、存取即時資訊（除非有特別設計）
- 用實際案例說明，不用卡通化對比

#### 1.4 AI 產業現況
- 這是目前全球最熱門的科技領域
- 全世界最聰明的人和最大的公司都在投入
- 學會理解和使用 AI，就像 20 年前學會用電腦一樣重要

### 玩（25 分鐘）

#### 1.5 Prompt 工程初體驗（10 分鐘）
**目的**：直觀感受「怎麼問」決定「AI 給你什麼」

**操作步驟**：
1. 打開 Claude AI（claude.ai）
2. 第一次嘗試 — 輸入模糊的 Prompt：「幫我寫一個自我介紹」
3. 觀察結果：很普通、很制式、不像自己
4. 第二次嘗試 — 輸入精確的 Prompt：「我是一個 [10/12] 歲的男生，喜歡 [他們的興趣]，擅長 [他們的強項]。請用輕鬆有趣的語氣幫我寫一段 100 字的自我介紹，要有個人特色」
5. 比較兩次結果的差異
6. **關鍵學習**：Prompt 越精確，AI 的回答越貼近你要的。這就是「Prompt 工程」的基本概念

**Prompt 工程基本原則（在此初次帶入，後續模組持續強化）**：
- 給 AI 背景資訊（你是誰、情境是什麼）
- 說清楚你要什麼格式和長度
- 一次一個任務，不要塞太多要求
- 不滿意就疊加修正，不用砍掉重來

#### 1.6 AI 能力實測（10 分鐘）
**目的**：了解 AI 的強項和弱項，培養不盲信 AI 的態度

**操作步驟**：
1. 準備 4 個不同類型的任務：
   - 數學題：一個有點難度的應用題
   - 邏輯推理：一個腦筋急轉彎
   - 程式邏輯：請 AI 寫一段 Scratch 的程式邏輯描述
   - 知識問答：一個他們熟悉領域的問題（方便驗證對錯）
2. 把這些問題丟給 Claude
3. 一起檢查 AI 的回答：哪些對、哪些錯、哪些「看起來對但其實有問題」
4. **關鍵學習**：AI 很強但不完美，使用 AI 的人需要有判斷能力

#### 1.7 AI vs AI 預熱（5 分鐘）
**目的**：為模組 2 的 LLM 比較做準備

**操作步驟**：
1. 選一個問題，同時丟給 ChatGPT 和 Claude
2. 快速比較：回答風格有什麼不同？
3. 留下懸念：「為什麼不同的 AI 會給不同答案？下個模組來深入研究」

## 模組 2：LLM 擂台賽（40 分鐘）

**目標**：認識各大語言模型的背景和強項，學會根據需求選擇工具

### 學（15 分鐘）

#### 2.1 什麼是 LLM
- 大語言模型就是 AI 界的「大腦」，不同公司訓練出不同的大腦，各有專長
- 就像不同品牌的手機都能打電話，但各有各的特色和強項

#### 2.2 五大陣營介紹

**OpenAI — ChatGPT**
- 2022 年底推出 ChatGPT，引爆整個 AI 時代
- 最早被大眾認識的 AI，用戶數最多
- 擅長：通用對話、創意寫作、廣泛的知識問答
- 代表模型：GPT-4o、o1、o3

**Anthropic — Claude**
- 由前 OpenAI 成員創立，特別強調 AI 安全
- 擅長：深度思考、長文分析、程式開發、精確推理
- 特色：回答比較謹慎和誠實，不確定的事會說不確定
- 代表模型：Claude Opus、Sonnet、Haiku

**Google — Gemini**
- 背後有 Google 搜尋引擎和 YouTube 的海量資料
- 擅長：多模態處理（文字 + 圖片 + 影片 + 聲音）、搜尋整合
- 特色：跟 Google 生態系統深度整合
- 代表模型：Gemini Ultra、Pro、Flash

**Meta — Llama**
- Facebook/Instagram 的母公司 Meta 開發
- 最大特色：**開源**，任何人都可以免費下載、使用、修改
- 意義：推動整個 AI 社群發展，讓小公司和研究者也能用到強大的模型
- 代表模型：Llama 3

**xAI — Grok**
- Elon Musk（Tesla、SpaceX 的創辦人）成立的 AI 公司
- 整合 X（以前的 Twitter）的即時資訊
- 特色：回答風格比較大膽直接
- 代表模型：Grok

#### 2.3 模型大小的概念
- 模型有「參數量」，可以想成大腦裡神經連結的數量
- 越大通常越聰明，但也越慢、越貴
- 所以同一家公司會出大中小三種模型（例如 Claude 的 Opus/Sonnet/Haiku），讓使用者根據需求選擇

#### 2.4 開源 vs 閉源
- **閉源**（ChatGPT、Claude、Gemini）：公司自己掌控，使用者付費使用，模型內部細節不公開
- **開源**（Llama）：程式碼公開，任何人可以使用和修改
- 為什麼這件事重要：影響到誰能使用 AI、AI 的發展方向、以及安全性的把關方式

### 玩（25 分鐘）

#### 2.5 LLM 擂台實測（15 分鐘）
**目的**：親手比較不同 AI 的表現差異

**操作步驟**：
1. 準備 5 個不同類型的任務：
   - **創意寫作**：用 50 個字寫一個恐龍穿越到現代的故事開頭
   - **數學**：一道需要多步驟的數學應用題
   - **程式邏輯**：描述一個 Scratch 遊戲的設計邏輯
   - **翻譯**：一段中文翻成英文，要求口語化
   - **知識問答**：一個他們感興趣的領域的深度問題
2. 兩兄弟分工：一人操作 ChatGPT，一人操作 Claude
3. 同一個 Prompt 同時送出，記錄兩邊的回答
4. 一起比較每題的結果

#### 2.6 建立評分表（10 分鐘）
**目的**：學會系統化地評估 AI，這份表就是學習筆記的第一頁

**操作步驟**：
1. 打開一個文字編輯器或 Google Docs
2. 自己設計評分標準（引導但不規定）：
   - 正確性（1-5 分）
   - 回答品質/深度（1-5 分）
   - 有趣程度（1-5 分）
   - 回答速度（1-5 分）
3. 把 5 個任務的比較結果填入表格
4. 計算總分，討論結論
5. **關鍵學習**：沒有「最好的 AI」，只有「最適合這個任務的 AI」

## 模組 3：Claude 全產品探索（60 分鐘）

**目標**：完整認識 Claude 生態系統的六大產品，每個都實際體驗

### 學（20 分鐘）

#### 3.1 Claude 生態系統總覽

先建立清楚的分類架構：

| 產品 | 定位 | 適合誰 |
|------|------|--------|
| **Claude AI（claude.ai）** | 網頁版，直接對話、上傳檔案、分析圖片 | 所有人 |
| **Claude Desktop** | 電腦 App，可讀取本機檔案，整合日常工作流 | 日常使用者 |
| **Claude Code** | 終端機裡的 AI 程式助手，直接讀寫程式碼、執行指令 | 開發者 |
| **Projects** | 在 claude.ai 建立專案，整理文件和對話，AI 有持續記憶 | 需要長期管理任務的人 |
| **Cowork** | Claude 在背景自動執行任務，完成後通知你 | 想提升效率的人 |
| **Dispatch** | 同時派出多個 Claude 平行處理不同任務 | 進階使用者 |

#### 3.2 產品之間的關係
- **claude.ai 是大本營** — 最基本的使用方式，瀏覽器打開就能用
- **Desktop 是本機版** — 跟 claude.ai 類似，但裝在電腦上，可以存取本機檔案
- **Claude Code 是開發專用通道** — 在終端機（Terminal）裡面跑，專門用來寫程式
- **Projects / Cowork / Dispatch** — 大本營裡的進階功能，讓 Claude 的能力延伸

#### 3.3 什麼時候用哪個
- 想問一個問題、聊天 → **Claude AI**
- 要分析電腦裡的檔案 → **Claude Desktop**
- 寫程式、做開發 → **Claude Code**
- 長期專案、需要 AI 記住前面的內容 → **Projects**
- 給一個耗時任務讓 AI 在背景做 → **Cowork**
- 同時有好幾個任務要處理 → **Dispatch**

### 玩（40 分鐘）

#### 3.4 Claude AI 體驗（7 分鐘）
**目的**：熟悉最基本的 Claude 介面

**操作步驟**：
1. 打開 claude.ai（前面模組應該已經用過了，這裡深入探索介面）
2. 認識介面元素：
   - 對話視窗：輸入文字跟 Claude 對話
   - 模型選擇：可以切換 Opus / Sonnet / Haiku，跟模組 2 學的大中小對應
   - 附件按鈕：可以上傳檔案和圖片
3. 實際操作 — 上傳一張照片（例如寵物、房間、或任何東西），請 Claude 描述這張照片
4. 實際操作 — 貼一段英文文章，請 Claude 翻譯並解釋裡面的文法
5. **學到什麼**：claude.ai 是最通用的入口，大部分事情都能在這裡完成

#### 3.5 Claude Desktop 體驗（7 分鐘）
**目的**：體會桌面版跟網頁版的差異

**操作步驟**：
1. 開啟 Claude Desktop App（如果還沒安裝，先從官網下載安裝）
2. 介面導覽：跟 claude.ai 長得很像，但它是一個獨立的 App
3. 實際操作 — 從 Finder/檔案總管拖曳一個檔案進去（例如一個 PDF 或文字檔），請 Claude 幫忙摘要
4. 感受差異：不用打開瀏覽器、不用上傳，直接拖就好
5. **學到什麼**：Desktop 版適合要頻繁使用 Claude 的人，少了瀏覽器的干擾

#### 3.6 Projects 體驗（7 分鐘）
**目的**：理解「專案」的概念 — AI 不只能單次對話，還能長期合作

**操作步驟**：
1. 在 claude.ai 左側找到 Projects，點擊建立新專案
2. 命名為「我的 AI 學習筆記」
3. 設定 Project Instructions（專案指令）：告訴 Claude「你是我的學習助手，請用繁體中文回答，語氣輕鬆但有深度」
4. 上傳模組 2 做的 LLM 評分表
5. 在 Project 裡跟 Claude 對話：「請根據我的評分表，幫我整理一份 LLM 比較總結」
6. **關鍵體驗**：Claude 記得你上傳的資料，可以引用它。這就是 Project 的核心價值 — 持續的記憶和上下文
7. **學到什麼**：Projects 適合需要長期追蹤的任務，AI 不會每次都從零開始

#### 3.7 Cowork 體驗（6 分鐘）
**目的**：體驗「讓 AI 在背景工作」的模式

**操作步驟**：
1. 在 claude.ai 開啟一個對話
2. 給 Claude 一個需要花點時間的任務：
   - 例如：「請幫我整理一份完整的 AI 學習大綱，包含 10 個主題，每個主題列出 3 個重點和 2 個練習活動」
3. 在回答生成時，注意介面上的 Cowork 選項（通常在對話視窗旁邊或上方，具體位置可能隨版本更新變動 — 課前請先確認當前 UI）
4. 啟用後，觀察：可以切到其他分頁或開新對話，Claude 在背景繼續工作
5. 完成時會收到通知，回來看結果
6. **學到什麼**：Cowork 讓你不用盯著 AI 等回答，適合比較大的任務

> **注意**：Cowork 需要 Claude Pro 以上方案。如果無法使用，由講師示範畫面即可。

#### 3.8 Dispatch 體驗（6 分鐘）
**目的**：體驗「同時派出多個 Claude」的威力

**操作步驟**：
1. 在 claude.ai 找到 Dispatch 功能入口（通常在左側欄或對話選單中，具體位置可能隨版本更新變動 — 課前請先確認當前 UI）
2. 建立多個平行任務：
   - 任務 A：把一段中文翻譯成英文
   - 任務 B：用這段文字寫一首短詩
   - 任務 C：列出這段文字中提到的所有關鍵概念
3. 同時啟動，觀察：三個任務同時在跑，不用排隊等
4. 結果出來後，比較三個不同方向的產出
5. **學到什麼**：Dispatch 就像同時有好幾個助手幫你做不同的事

> **注意**：Dispatch 需要 Claude Pro 以上方案。如果無法使用，由講師示範畫面即可。

#### 3.9 Claude Code 預告（7 分鐘）
**目的**：認識 Claude Code 的介面和基本概念，為模組 4 做準備

**操作步驟**：
1. 打開 Terminal（Mac 的終端機）
2. 展示 Claude Code 的啟動方式
3. 解釋 Terminal 是什麼：跟用滑鼠點按鈕不同，這裡是用打字跟電腦溝通。開發者很多時候偏好這種方式，因為更快、更精確
4. 展示 Claude Code 的基本互動：問它一個簡單問題，看它在 Terminal 裡怎麼回答
5. 重點預告：Claude Code 最厲害的地方是它能直接讀寫你電腦上的檔案、執行程式指令。下個模組會深入學習
6. **學到什麼**：Claude Code 是開發者的工具，用文字指令操作，能力比網頁版更強大

## 模組 4：GitHub 冒險 + Claude Code + Branch 專題（70 分鐘）

**目標**：從零搞定 GitHub，學會 Claude Code 與 GitHub 的協作流程，深入理解 Branch

### 學（15 分鐘）

#### 4.1 GitHub 是什麼
- 全世界最大的程式碼倉庫平台
- 像程式設計師的「雲端硬碟」，但多了一個超能力：**版本控制**
- 每一次修改都有紀錄，可以隨時回到過去任何一個版本

#### 4.2 為什麼 GitHub 很重要
- 幾乎所有軟體公司都用它管理程式碼
- 全球最大的開源社群大本營 — Linux、Python、React 這些改變世界的專案都在上面
- 你的 GitHub 就是你的程式作品集，未來學程式、找工作都會看

#### 4.3 Git vs GitHub
- **Git** — 版本控制「工具」，裝在你的電腦上
- **GitHub** — 版本控制「平台」，把 Git 放到雲端，讓大家能協作
- 就像 Word 是軟體，Google Docs 是平台。Git 是軟體，GitHub 是平台

#### 4.4 核心概念

**Repository（Repo）**
- 一個專案的完整資料夾，所有檔案和所有修改紀錄都在裡面
- 就像一個超級資料夾，除了檔案本身，還記錄了「誰在什麼時候改了什麼」

**Commit**
- 一次「存檔點」，附帶一段說明文字描述你做了什麼改動
- 就像遊戲的存檔：你可以隨時回到任何一個存檔點
- 好的 Commit 訊息很重要 — 讓未來的你（或其他人）知道當時為什麼做這個改動

**Push**
- 把本機電腦上的存檔（Commit）上傳到 GitHub 雲端
- 上傳之後，其他人就能在 GitHub 網站上看到你的變更

**Pull**
- 把 GitHub 雲端上最新的版本拉到你的本機電腦
- 如果有人在 GitHub 上做了修改，你用 Pull 就能拿到最新版

**Clone**
- 把 GitHub 上的一個 Repo 完整複製到你的本機電腦
- 跟一般的「下載」不同：Clone 保留了所有版本紀錄和 Git 的連結

**Branch（分支）— 詳見 4.8 Branch 專題**

### 玩（55 分鐘）

#### 4.5 GitHub 註冊與設定（10 分鐘）
**目的**：擁有自己的 GitHub 帳號

**操作步驟**：
1. 打開 github.com
2. 點擊 Sign Up
3. 輸入 Email → 設定密碼 → 選擇使用者名稱
   - 使用者名稱建議：簡短好記、用英文、這會成為你網址的一部分（`github.com/你的名字`）
4. 完成信箱驗證
5. 設定 Profile：
   - 上傳大頭貼（或選一個預設的）
   - 寫一段 Bio：「10 歲，正在學 AI 和程式設計」之類的
6. 認識 GitHub 介面：
   - 首頁（Dashboard）：最新動態
   - 你的 Profile 頁面：別人看到的你
   - Repositories 頁面：你所有的專案

#### 4.6 建立第一個 Repository（10 分鐘）
**目的**：在 GitHub 上建立自己的第一個專案

**操作步驟**：
1. 點右上角的「+」→ New Repository
2. 填寫設定：
   - **Repository name**：`my-ai-study-notes`
   - **Description**：「我的 AI 學習筆記」
   - **Public vs Private**：
     - Public：全世界都能看到
     - Private：只有你能看到
     - 建議選 Public — 這是學習紀錄，公開分享沒問題
   - **Initialize with a README**：打勾
     - README 是一個專案的「首頁說明」，別人打開你的 Repo 第一個看到的就是它
   - **.gitignore**：先跳過，後面會解釋
3. 點擊 Create Repository
4. 在 GitHub 網頁上直接編輯 README.md：
   - 點 README.md → 點鉛筆圖示（Edit）
   - 寫下：專案標題、自己的名字、這個 Repo 的用途
   - 這是用 Markdown 語法寫的 — 簡單介紹 `#` 是標題、`-` 是列表
5. 點 Commit changes → 寫一段 Commit 訊息：「新增個人簡介」
6. **關鍵體驗**：你剛剛完成了第一次 Commit！這個修改已經被永久記錄在歷史裡了

#### 4.7 Claude Code 登場 — 與 GitHub 串接（15 分鐘）
**目的**：學會用 Claude Code 操作 Git，體驗開發者的工作流

**操作步驟**：
1. 打開 Terminal
2. 啟動 Claude Code
3. **Clone Repo 到本機**：
   - 請 Claude Code：「幫我把 `github.com/[使用者名稱]/my-ai-study-notes` clone 到桌面」
   - 觀察：Claude Code 執行了一個 `git clone` 指令
   - 解釋 clone 跟下載的差異：clone 保留了 Git 的所有歷史紀錄和跟 GitHub 的連結
4. **新增檔案**：
   - 請 Claude Code：「在這個專案裡新增一個 `day1-notes.md` 檔案，內容是今天學到的 AI 基礎知識重點整理」
   - Claude Code 會自動建立檔案並寫入內容
   - 可以跟它來回修改：「加上 LLM 擂台賽的結果」「把格式弄漂亮一點」
5. **完成 Git 流程（add → commit → push）**：
   - 請 Claude Code：「幫我把這些修改 commit 並 push 到 GitHub」
   - 觀察 Claude Code 執行的每一步：
     - `git add` — 把檔案加入「準備存檔」的清單
     - `git commit` — 存檔，附上說明
     - `git push` — 上傳到 GitHub
6. **回到 GitHub 網頁驗證**：
   - 重新整理頁面，看到 `day1-notes.md` 出現了
   - **「哇」時刻**：你在 Terminal 裡用 AI 做的東西，已經到雲端上了

#### 4.8 Branch 專題 —「平行宇宙」（20 分鐘）
**目的**：深入理解 Git 最重要但最容易搞混的概念

**概念講解**：

**Branch 是什麼？**
- 想像你在寫一篇作文，目前的版本你很滿意，但想試試看把結尾完全改掉
- 你不想直接改原本的版本，怕改壞了回不去
- Branch 就是讓你「複製一條時間線」出來，在複製品上隨便改，原本的版本完全不受影響

**為什麼不直接複製貼上就好？**
- 手動複製沒辦法追蹤「從哪裡分出去的」、「改了什麼」
- Branch 厲害的地方：Git 會記住分支點、記住所有改動，最後還能把改動「合併」回來
- 如果你手動複製，改完要合併回去就得一行一行人工比對，非常容易出錯

**main 是什麼？**
- 每個 Repo 都有一個預設的主分支，叫做 `main`
- 這是你的「正式版本」，穩定的、確定沒問題的內容都放在 main
- 所有的實驗和開發都在其他 Branch 上做，做好了再合併回 main

**什麼時候要開 Branch？**
- 想嘗試新東西，但不確定會不會搞砸 → 開 Branch
- 多人協作，每個人在自己的 Branch 上做事 → 不會互相干擾
- 做完、確認沒問題了 → 合併（Merge）回 main

**實際操作（用 Claude Code）**：
1. **確認目前位置** — 請 Claude Code 確認目前在 main branch 上
2. **開一條新 Branch** — 請 Claude Code：「幫我建立一個叫 `experiment` 的新 branch 並切換過去」
   - 解釋命名慣例：用英文、短橫線分隔、名稱要描述用途（例如 `add-math-notes`、`fix-typo`）
3. **在新 Branch 上做修改** — 請 Claude Code 修改 `day1-notes.md`，加上一段新的內容（例如「模組 3 Claude 產品心得」）
4. **Commit 並 Push 這個 Branch** — 請 Claude Code 完成存檔和上傳
5. **切回 main** — 請 Claude Code：「切換回 main branch」
6. **關鍵時刻** — 打開 `day1-notes.md` 看看：**內容是舊的！** 剛才加的東西不見了！
   - 不是 bug，是因為那些改動在 `experiment` branch 上
   - 同一個資料夾、同一個檔案，切換 branch 後內容自動變回去
   - **這就是「平行宇宙」的感覺 — 這個「哇」時刻要讓他們親自體驗**
7. **合併（Merge）** — 請 Claude Code：「把 experiment branch 合併回 main」
   - 合併後再看 `day1-notes.md`：新內容出現了！兩個宇宙合而為一
8. **回到 GitHub 網頁驗證** — 看到 branch 的紀錄、合併的紀錄都完整保留

## Prompt 工程（貫穿全程）

不設獨立模組，融入每個環節：

| 模組 | Prompt 技能 | 怎麼融入 |
|------|------------|---------|
| 1 | 精確 vs 模糊 | 同一任務用不同 Prompt，比較結果 |
| 2 | 跨模型測試 | 同一 Prompt 丟不同 AI，觀察差異 |
| 3 | 情境化 Prompt | 在 Projects 裡設定 AI 角色和背景 |
| 4 | 指令式 Prompt | 用 Claude Code 時，精確描述要做什麼 |
| 5 | 實戰應用 | 用 Prompt 指揮 Claude Code 開發專案 |

**四大原則（每次用到就重複強調）**：
1. 給 AI 角色和背景資訊
2. 說清楚要什麼格式和長度
3. 一次一個任務，不要塞太多
4. 不滿意就疊加修正，不用砍掉重來
